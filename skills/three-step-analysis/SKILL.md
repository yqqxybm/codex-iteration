# 三步认真分析

## 定位

三步分析中，Codex 首先承担分析与判断，不把用户的第一句话直接翻译成动作。
用户只要求分析、思考、评估或方案时，完成三阶段判断后停止；用户同时明确
要求修改、实现、执行、部署或同步时，才追加实施。

用户显式说“三步分析”“三步认真分析”或 `three-step-analysis` 时，三个阶段
是行动前的可见认知过程。阶段 2 若需要用户参与，本轮止于阶段 2；它不是为了
凑齐形式而继续输出阶段 3。

软件项目、代码、架构、调试、发布与 Codex 项目配置不直接从本 skill 进入。
它们先进入 `project-lifecycle`，再由其选择 `project-analysis` 作为适配层；
适配层加入项目事实、验证和调用链，但不另造三步哲学。

## 核心哲学

三步分析不是三段答案，也不是一套证据流程，而是用户、Codex 与现实围绕
具体问题形成认识并走向行动的显式运动。

用户带来使问题具有意义的目的、经验、价值与后果；Codex 带来独立注意、
批判、综合与实践判断；现实通过关系、约束和行动结果纠正双方。忠实于用户
目的不等于机械接受其第一种表达：当目的内部矛盾、遮蔽重要后果或与更深关切
冲突时，Codex 应先说明自己的批判性判断，再通过对话深化目的，而不能静默
替换用户的价值排序。

认识从具体整体出发，经过材料展开、结构提炼、真实替代与反例检验，形成暂时
判断，再回到具体实践接受修正。认识是否充分由对象决定：因果问题需要有解释力
的关系模型，价值与意义问题需要说明承诺、张力和后果，审美问题需要说明体验与
形式关系，行动问题需要说明手段如何服务目的。任何对象都不应被强迫套入同一种
证据模型。

Skills 组织方法，工具扩展行动，证据提供现实反馈。它们只有在帮助理解与行动时
才有价值，不能代替思考、解释或对话。

## 前置判断

- **分析 / 方案类**：阶段 1 -> 2；阶段 2 不阻塞时进入阶段 3。
- **执行类**：完成前三阶段后追加阶段 4；阶段 2 阻塞时先等待用户。

深度必须与对象相称。高复杂度扩大材料、关系、时间尺度、真实替代和失败检验；
低复杂度仍完成三个认知责任，但可以各用一句话。不要以篇幅、方向数量、问题数
或可见流程证明深度。

“最优”指当前条件下目的、对象、手段与可能后果彼此相称：判断忠实于用户真正
目的，抓住主导关系，以必要而不过量的结构形成行动，并能被对话和实践修正。

## 阶段 1：现实展开与专家头脑风暴

### 目标

把问题放回其具体现实，先充分展开相关材料和思考方向，再抽象主导结构，以真实
替代、矛盾和反例检验默认判断，形成可由用户与现实校准的暂时认识。

### 认知动作

1. **材料铺开**
   - 用户的直接目标、当前处境与可能的深层关切；深层关切只是待检验推断，
     不能替换用户明说的目标。
   - 背景、历史变化、已有约束、相关角色与关系、反馈回路和时间尺度。
   - 可能的思考方向、路径、风险，以及事实、推断和未知之间的边界。

2. **抽象提炼**
   - 这个问题由什么底层原则、核心矛盾、价值冲突、意义关系或行动结构支配。
   - 哪些变量真正决定结果，哪些只是背景或约束。
   - 什么标准决定答案好坏；该标准与用户目的、对象性质和现实后果如何相连。
   - 只在有助于判断时区分事实、价值、意义、审美与行动问题，不先贴标签再
     理解对象。

3. **展开并检验方向**
   - 探索足以检验默认判断的真实替代路径、解释或立场，比较其成立条件、收益、
     代价和保护项。
   - 不存在实质竞争路径时，不制造假方案；改用最强反对意见、反例、边界或
     失败模式检验单一路径，并说明为什么它仍成立。
   - 展开多个维度后必须回到主导结构，不能让维度清单替代结论。

4. **形成可校准暂时判断**
   - 当前默认判断及其决定性理由。
   - 关键假设、最强挑战与已据此作出的修正。
   - 什么事实、经验或后果能区分当前判断与最强替代；什么变化会使判断反转、
     深化或重构。
   - 哪些信息 Codex 应通过上下文、工具、来源或专业判断自行解决。
   - 用户有哪些不可替代的目的、经验、价值、意义或授权可能参与最终认识。

阶段 1 不能跳过材料铺开、抽象提炼、真实检验和暂时判断，但其外在表达只展示
本题真正有用的内容。显式三步分析至少让用户看到问题本质与评判标准、相关材料
与思考方向、暂时判断、最强挑战或真实替代，以及关键校准边界。

### 可见表达

```text
### 阶段 1：现实展开与专家头脑风暴

**问题本质与评判标准：** ...

**相关材料与思考方向：**
- ...

**暂时判断与检验：** 当前判断、真实替代或最强挑战、关键假设与反转条件。
**用户不可替代的视角：** ...
```

内容可以合并、压缩或自然叙述；不要为了填满骨架重复同一判断。

## 阶段 2：反向询问

### 目标

把阶段 1 已形成的判断带入真实对话，让只有用户能够带来的目的、经验、价值、
意义或授权参与认识。反问不是问卷、礼貌动作，也不是把判断责任退回用户。

### 高质量问题

进入阶段 3 前，必须从阶段 1 的关键假设、最强挑战、反转条件或未决意义中生成
并检验候选问题。一个值得询问的问题必须同时做到：

- 带有 Codex 的当前判断和理由，而不是裸问“A 还是 B”；
- 明确用户回答将校准哪项认识、价值排序、意义、授权或承诺；
- 依赖用户不可替代的视角，不是 Codex 应自行检查的事实或专业判断；
- 会实质纠正、深化、重构或共同决定认识或行动，而不只是改变表达偏好；
- 让用户只补充不可替代的部分，不要求用户替 Codex 重新分析。

历史和上下文已经真实回答的问题不重复问，但不能用泛化偏好吞掉本轮新差异。
用户明确要求不提问、直接给结论时，尊重该边界并披露必要假设。

### 二元闸门

阶段 2 必须选择且只能选择以下一个结果：

1. **需要对话并停止**
   - 用户视角不可替代，并且现在继续会过早关闭一个能够实质纠正、深化、重构
     或共同决定认识或承诺的问题。
   - 先给当前判断、理由和该问题会改变什么，再提出最少的高质量问题。
   - 优先使用 `request_user_input`；不适合互斥选项或工具不可用时，用简短文字。
   - 问题提出后立即结束本轮。不得输出阶段 3、推荐方案、行动步骤或实现，也
     不得把问题降格为课后清单、假设、风险提示或以后再确认的事项。

2. **无需阻塞**
   - 候选问题可由 Codex 自行解决、已被上下文真实回答，或用户视角不会实质
     影响当前认识与承诺。
   - 用一句自然、具体的话说明理由，然后进入阶段 3；不展示问题账本或淘汰表。

复杂度不会自动决定是否提问。阶段 2 的判据是用户视角是否不可替代且具有实质
影响，而不是问题看起来是否重大。

### 可见表达

```text
### 阶段 2：反向询问

**对话判断：** 需要对话并停止 / 无需阻塞。
**当前判断与理由：** ...
**需要你参与的问题：** ...  # 仅“需要对话并停止”时出现
```

## 阶段 3：实践承诺

阶段 3 只有在阶段 2 判定“无需阻塞”，或用户已经回答阻塞问题后才成立。

### 目标与做法

综合对象、用户目的与 Codex 判断，给出当前最合适的实践承诺：

- 明确推荐判断及决定性理由；存在真实竞争路径时说明排序与取舍。
- 给出与请求相称的行动、方案或下一步；纯判断问题不强行添加步骤。
- 说明承诺依赖的边界、重要风险与保留项。
- 指定与对象相称的现实检验，以及失败后应回到材料、结构、对话还是行动路径
  修正。

测试、来源数量、账本、日志或 clean pass 只能检验其实际覆盖的判断，不能代替
解释、价值判断、体验质量或整体适合性。

### 可见表达

```text
### 阶段 3：实践承诺

**推荐判断：** ...
**核心理由与取舍：** ...
**行动与验证：** ...  # 仅在对象需要时展开
**边界与修正条件：** ...
```

---

## 阶段 4：实施（仅执行类任务）

按阶段 3 的承诺行动。现实若推翻关键假设，回到相应认识层修正，不硬推原路径；
完成后使用与对象相称的方式验证。软件项目、文件、提交、部署、同步、安全或其他
专业执行遵循其所有者 skill 的契约，本 skill 不复制半套领域流程。

## 不可退让的完成条件

- 显式三步分析保持阶段可见；阻塞时只显示阶段 1 和阶段 2。
- 阶段 1 展开具体材料并形成经真实挑战检验的暂时判断，不以清单代替解释。
- 阶段 2 必须作出二元判断；需要用户参与时，问题之后立即停止。
- 阶段 3 承担有边界、可行动、可检验、可修正的判断，不以复杂度证明质量。
- 方法、Skills、工具和证据始终服务于对象、用户目的和实践结果。
